# ゲーム要件定義書（1ページ・記入例）

最終更新: 2026-07-27
作成者: Project Team
版数: v1.0
状態: Draft
対象プロダクト: Neon Board Arcade（Next.js版）

---

## 1. 目的

- 課題: ブラウザで、インストール不要かつ短時間で遊べる対戦/協力ゲーム体験を提供する。
- 遊ぶ理由: 1つのURLで複数ゲームを切り替え、ソロ・ローカル・オンライン対戦を状況に応じて選べる。
- 目標KPI:
  - D1継続率: >= 25%
  - 1セッション平均プレイ時間: >= 12分
  - 初回プレイ完了率: >= 85%

## 2. 対象範囲

- 対象（このフェーズで必ず出す）:
  - Next.jsフロント（apps/web）で主要ゲームをプレイ可能にする。
  - ルーム対戦（6桁コード、公開/非公開、観戦）を提供する。
  - クラウド保存API（プロフィール/戦績）を利用可能にする。
- 対象外（このフェーズではやらない）:
  - bikeRunnerのNext移行。
  - ネイティブアプリ化（iOS/Androidストア配布）。

## 3. 対象ユーザー

- 主対象ユーザー: PC/スマホで手軽に遊びたいライトゲーマー、友人同士で対戦したいユーザー。
- 利用シーン: 自宅や休憩時間に、短時間で1人プレイまたは友人とオンライン対戦。
- 価値仮説: 「短時間の空き時間でも、URLに入るだけでゲーム開始でき、準備コストなく遊べる」

## 4. コア体験

- コアループ:
  1. ゲームを選ぶ
  2. ソロまたはルームを開始する
  3. クリック/タップ中心で1試合遊ぶ
  4. 結果確認して再戦または別ゲームへ移る
- 主操作:
  - 主要入力はクリック/タップ
  - キーボード対応: 一部ゲームのみ（補助的）
- 1プレイ想定時間: 3 - 15分
- 勝敗条件:
  - 勝利: 各ゲーム固有の勝利条件を満たす
  - 敗北: 各ゲーム固有の敗北条件を満たす、または相手勝利条件達成

## 5. 機能要件（Must/Should）

### Must（必須）

- [ ] FR-001: Next.js版で主要ゲーム（docs/next-migration-status.md記載）を起動・プレイできる。
- [ ] FR-002: ルーム作成/参加/観戦ができ、2人対戦ゲームで同期破綻なく進行できる。
- [ ] FR-003: クラウド保存APIによりプロフィール・戦績の保存/読込ができる。

### Should（できれば）

- [ ] FR-101: クイックマッチで公開ルームに自動参加できる。
- [ ] FR-102: 再戦投票・ドロー合意をルームで利用できる。

## 6. 非機能要件

- 対応環境: Desktop / Mobile Web（最新2世代の主要ブラウザ）
- 性能:
  - 初期表示: <= 3秒（家庭内Wi-Fi相当）
  - 入力応答: <= 100ms
  - フレームレート目標: >= 30FPS
- 信頼性:
  - 通信一時断時は再接続を試み、失敗時はロビー復帰導線を表示
  - 保存失敗時は再試行導線とエラーメッセージを表示
- アクセシビリティ:
  - 主要ボタンのクリック/タップ領域 >= 40px
- セキュリティ/プライバシー:
  - 保存データ: ユーザーID、表示名、戦績、ゲーム進行に必要な最小情報
  - パスワードはハッシュ保存（平文保存しない）

## 7. 受け入れ基準

- AC-001（FR-001）: Given トップ画面, When ゲームを選択, Then 該当ゲームが開始し1試合完了できる。
- AC-002（FR-002）: Given ホストとゲスト2端末, When 同一ルームで対戦開始, Then 双方で同一進行と同一勝敗結果になる。
- AC-003（FR-003）: Given 認証済みユーザー, When 保存後に再読込, Then 直近保存値が復元される。
- AC-004（NFR）: ミドルレンジ端末で初期表示3秒以内、主要操作応答100ms以内。
- 完了定義（DoD）:
  - [ ] Must要件がすべて合格
  - [ ] Blocker/Criticalバグが0件
  - [ ] ルーム回帰チェック（docs/room-e2e-regression-checklist.md）を完了

## 8. 計測要件

- 計測イベント:
  - game_start
  - game_end
  - room_create
  - room_join
  - save_success
  - save_error
- 成功ライン: 1週間でセッションの80%以上がエラー離脱なく終了

## 9. 制約とリスク

- 技術制約:
  - Nextフロントとルーム/クラウドの分離起動構成を維持する必要がある。
  - 共有モードと分離モードの双方で動作保証が必要。
- スケジュール制約: 既存ゲームの互換性維持を優先し、大規模UI刷新は後続フェーズ。
- 主要リスクと対策:
  - リスク: ルーム同期ズレ / 対策: リクエスト型同期対象ゲームを優先検証
  - リスク: ポート競合 / 対策: 起動ガイド通りの運用と競合検知手順を徹底
