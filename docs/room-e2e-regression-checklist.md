# ルーム対戦E2E回帰チェックリスト

最終更新: 2026-07-24

目的:
- ルーム対戦機能の回帰を、毎回同じ手順で短時間に検出する。
- 特に guest -> host 判定方式の同期ズレを早期に見つける。

対象:
- オセロ
- 五目並べ
- チェス
- 将棋
- UNO
- 大富豪

---

## 1. 事前準備

### 1.1 起動構成

以下のどちらかで起動する。

1. 分離起動
- `npm run cloud`
- `npm run room`
- `npm run dev:web`

2. フル起動タスク
- VS Codeタスク: Run Web Game Full Stack (Cloud + Room + Dev)

### 1.2 検証クライアント

- クライアントA: 通常ウィンドウ（host想定）
- クライアントB: シークレット/別プロファイル（guest想定）
- 任意クライアントC: 観戦検証用（spectator想定）

### 1.3 初期条件

- 3クライアントとも同一URLへアクセスする。
- ルーム接続前に、表示名を判別しやすい文字列にする（例: HostA / GuestB / SpecC）。
- ローカル保存の古い roomCode が残っている場合は更新後に再接続する。

## 2. 共通ルーム検証

### 2.1 ルーム作成/参加

1. Aで公開ルームを作成する。
2. Bで同一6桁コードへ参加する。
3. Cで観戦参加する（任意）。

期待結果:
- Aのロールが host、Bが guest、Cが spectator になる。
- 参加者一覧が全クライアントで一致する。
- ルーム状態が接続済みになる。

### 2.2 公開/非公開と招待リンク

1. Aで非公開へ切替。
2. Aで招待リンクをコピー。
3. Bを一度切断し、招待リンク経由で再参加。

期待結果:
- 招待リンク経由の参加は成功する。
- 非招待トークンでの新規参加は拒否される。

### 2.3 クイックマッチ（任意）

1. Bでクイックマッチ開始。

期待結果:
- 公開ルームへ接続される。
- 非公開ルーム候補はスキップされる。

### 2.4 観戦制御

1. Cで各ゲーム画面を開く。
2. 盤面/手札操作を試みる。

期待結果:
- Cの操作は拒否される（読み取り専用）。
- 観戦チャットは送信できる。

### 2.5 チャット/モデレーション

1. A/Bで通常チャット送信。
2. Cで観戦チャット送信。
3. 同一短文を短時間連投してレート制限を確認。

期待結果:
- プレイヤーチャットと観戦チャットが分離される。
- 連投時に送信制限メッセージが出る。

## 3. ゲーム別E2E手順

共通前提:
- Aが host、Bが guest。
- guestは直接確定せず、host判定で着手が適用されることを確認する。

### 3.1 オセロ

1. Aがオセロ開始。
2. A手番でAが合法手を1回打つ。
3. B手番でBが合法手を1回打つ。
4. Bが手番外で打てないことを確認。

期待結果:
- 双方で盤面と手番表示が一致する。
- B操作時に host 判定待ちを経由して確定する。
- 手番外操作は拒否される。

### 3.2 五目並べ

1. A/Bで交互に3手ずつ置く。
2. Bが手番外で置けないことを確認。

期待結果:
- 石配置と現在手番が双方一致。
- guest着手は host 反映後に確定。

### 3.3 チェス

1. Aで白の駒を1手進める。
2. Bで黒の駒を1手進める。
3. 非合法移動を1回試す。

期待結果:
- 合法手のみ適用される。
- 盤面状態が双方一致。
- 非合法手は拒否メッセージになる。

### 3.4 将棋

1. Aで先手を1手。
2. Bで後手を1手。
3. 非合法移動を1回試す。

期待結果:
- 合法手のみ適用。
- 盤面・手番が双方一致。

### 3.5 UNO

1. A手番で出せるカードを1枚出す。
2. B手番でカードを出すか、出せない場合はドローする。
3. 手番外操作を試す。

期待結果:
- 手札枚数、場札、手番表示が双方一致。
- B操作は host 判定後に反映。
- 手番外は拒否。

### 3.6 大富豪

1. Aが場に1枚出す。
2. Bが上位札で返す、またはパスする。
3. 手番外操作を試す。

期待結果:
- 場札、手札枚数、手番表示が双方一致。
- B操作は host 判定後に反映。
- 手番外は拒否。

## 4. 再戦/ドロー投票

### 4.1 再戦投票

1. A/Bで再戦投票を送る。

期待結果:
- 投票状態が両者で一致。
- 必要数到達で再戦開始イベントが反映。

### 4.2 ドロー投票

1. Aがドロー投票を送る。
2. Bが同意投票。

期待結果:
- 同意成立時にドロー確定イベントが反映。

---

## 5. 回帰判定基準

以下のいずれかが発生した場合、回帰ありと判定する。

- A/Bで盤面または手札状態が不一致。
- 手番表示が一致しない。
- guest操作が host 判定を経ずに確定する。
- spectatorが操作できてしまう。
- 再戦/ドロー投票状態が片側だけ更新される。
- ルーム参加者一覧がクライアント間で不一致。

---

## 6. 障害切り分けメモ

### 6.1 接続不可

- `room` サーバー稼働確認。
- ポート競合確認（既定: 8788）。
- URLクエリの `roomServer` 上書き有無を確認。

### 6.2 同期ズレ

- host/guestロールが想定どおりか確認。
- guest側が待機メッセージを経由しているか確認。
- ルーム再接続後に再現するか確認。

### 6.3 招待リンク不具合

- ルームが非公開か確認。
- 招待トークン有効期限切れを疑う。
